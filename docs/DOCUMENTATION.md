## ۲. فناوری و ساختار کد

- **Next.js 16** (App Router، رندر سمت سرور در هر درخواست — `force-dynamic`)
- **Prisma 7** + **PostgreSQL** (روی Neon)
- **Tailwind CSS v4** با توکن‌های رنگی CSS (`--background`، `--card`، `--accent` و …)
- **next-themes** برای حالت روشن/تیره، **framer-motion** برای انیمیشن (به شکل `LazyMotion` + `m`؛ قابلیت‌ها بعد از رندر بارگذاری می‌شوند)، **sharp** برای پردازش تصویر
- فونت **Vazirmatn** با `next/font` (سلف‌هاست، بدون stylesheet خارجی)
- میزبانی روی **Vercel**؛ فایل‌های بزرگ (PDF) روی **Vercel Blob**

```
src/
  app/
    (main)/        صفحات سایت عمومی (layout با هدر، فوتر، منوی موبایل، ردیاب تماس)
    admin/         پنل ادمین (layout جدا: منوی کناری، هدر، اعلان‌ها)
    api/           APIها
    media/[file]/  سرو تصاویر آپلودی از دیتابیس
    sitemap.ts     robots.ts   opengraph-image.tsx
  features/        کامپوننت‌های بخش‌ها (products، prices، blog، consult، leads، admin/...)
  widgets/         هدر، فوتر، منوی ادمین، بخش‌های صفحه اصلی
  shared/
    config/site.ts تنظیمات ثابت سایت (نام، تلفن‌ها، آدرس‌ها، دسته‌های فعال)
    lib/           منطق مشترک (data، seo، price-board، catalog، leads، auth، …)
    ui/            کامپوننت‌های پایه
  generated/prisma/ خروجی خودکار prisma generate
```

**قراردادهای عملکرد و موبایل:**

- محتوای بالای صفحه (هیرو، `PageHero`، گالری محصول، متن مقاله) **انیمیشن ورود ندارد**؛ چیزی که با `opacity: 0` شروع شود تا اجرای جاوااسکریپت دیده نمی‌شود و LCP/Speed Index را خراب می‌کند. انیمیشن فقط برای بخش‌های پایین‌تر (`whileInView`) و پنجره‌ها.
- در import از framer-motion همیشه `m as motion` (نه `motion`)، وگرنه کل کتابخانه به باندل اولیه برمی‌گردد.
- هر `grid` که ستون‌هایش فقط برای `sm:`/`lg:` تعریف شده، `grid-cols-1` پایه می‌خواهد؛ وگرنه در موبایل ستون به اندازه پهن‌ترین محتوا کش می‌آید.
- برای تایید کاربر از `useConfirm()` (`shared/ui/ConfirmDialog.tsx`) استفاده شود، نه `confirm()` مرورگر — دسکتاپ پنجره وسط، موبایل bottom sheet.

**قرارداد طراحی:** سایت عمومی و پنل ادمین هر دو داخل کلاس `.site` رندر می‌شوند (لایه طراحی صنعتی در `globals.css`: پالت گرافیتی، گوشه‌های تیز، رنگ آکسنت). رنگ‌ها همیشه از توکن‌ها خوانده می‌شوند (`bg-[var(--card)]`، `text-[var(--muted-foreground)]`)، نه رنگ ثابت؛ پس تغییر تم یا رنگ آکسنت همه‌جا یکجا اعمال می‌شود. کلاس‌های `dark:` تیلویند همراه کلاس `.dark` (دکمه تغییر تم) کار می‌کنند.

## ۳. سایت عمومی

| صفحه | مسیر | کارکرد |
|---|---|---|
| خانه | `/` | هیرو با تابلوی قیمت زنده، آخرین قیمت‌ها، دسته‌ها (کاروگیت کاشی بزرگ اول)، محصولات ویژه، خدمات، برندها، مقالات، معرفی کارخانه، متن سئو |
| محصولات | `/products` | همه محصولات با فیلتر دسته و جستجو (کاروگیت اول) |
| دسته | `/products/[category]` | محصولات دسته + جدول قیمت روز (فقط دسته فعال) یا پیام «به زودی» با دکمه استعلام |
| محصول | `/products/[category]/[slug]` | گالری، مشخصات، خلاصه و جدول قیمت زنده، نمودار نوسان، سوالات متداول، محصولات مرتبط، نوار اقدام موبایل |
| همه دسته‌ها | `/categories` | کارت دسته‌ها با برچسب «به زودی» |
| لیست قیمت | `/prices` | جدول قیمت همه خطوط فعال با پرش سریع؛ عنوان از دسته‌های فعال ساخته می‌شود |
| وبلاگ | `/blog`، `/blog/[slug]` | مقاله متنی یا PDF، سوالات متداول مقاله، لینک به دسته‌های نام‌برده در مقاله و لیست قیمت |
| پروژه‌ها | `/projects`، `/projects/[slug]` | پروژه‌های انجام‌شده (در سایت‌مپ فقط وقتی پروژه‌ای ثبت شده باشد) |
| سوالات متداول | `/faq` | سوالات با دسته‌بندی و جستجو؛ پاسخ‌ها همیشه داخل HTML (برای خزنده گوگل) |
| تماس | `/contact` | فرم تماس، تلفن‌ها، آدرس دفتر و کارخانه |
| درباره ما / خدمات | `/about`، `/services` | معرفی شرکت و خدمات |
| قوانین / حریم خصوصی | `/terms`، `/privacy` | شرایط خرید (قیمت نهایی هنگام سفارش تایید می‌شود) |
| جستجو | `/search` | جستجوی محصول، مقاله و پروژه — `noindex` |

**اجزای مشترک:**

- **فرم مشاوره** (`ConsultProvider`): از دکمه‌های «مشاوره / استعلام / سفارش» در کل سایت باز می‌شود؛ نام و موبایل می‌گیرد و پیام در پنل ثبت می‌شود.
- **دکمه‌های شناور تماس** (دسکتاپ) و **نوار پایین** (موبایل).
- **فوتر**: هر ستون یک‌بار در HTML (در موبایل تاشو)، هر شماره تلفن با لینک `tel:` جدا، دسته‌های «به زودی» با برچسب.
- **حالت روشن/تیره** و **رنگ آکسنت** قابل انتخاب (رنگ از پنل ← «رنگ‌بندی سایت» برای همه بازدیدکنندگان ذخیره می‌شود).

## ۴. کاتالوگ: محصول فعال و «به زودی»

**محل تنظیم:** `src/shared/config/site.ts` ← `activeCategorySlugs` (الان فقط `corrugated-pipes`).

| | دسته فعال | دسته «به زودی» |
|---|---|---|
| ترتیب نمایش | همیشه اول (به ترتیب همین لیست) | بعد از فعال‌ها، به ترتیب پنل ادمین |
| قیمت | در ساعت فروش نمایش داده می‌شود | هیچ‌جا — نه صفحه، نه API زنده، نه تاریخچه، نه schema |
| برچسب | «موجود در انبار» / «ناموجود» | «به زودی» |
| دکمه اصلی | «ثبت درخواست مشاوره و خرید» | «استعلام و اطلاع از زمان عرضه» |
| عنوان صفحه دسته | «قیمت X \| جدول سایز و خرید عمده» | «X \| مشخصات و استعلام (به زودی)» |
| صفحه در گوگل | ایندکس | ایندکس (برای حفظ سئو) |

**فعال کردن یک دسته جدید:** اسلاگ آن را به `activeCategorySlugs` اضافه و دیپلوی کنید؛ ترتیب، قیمت، برچسب‌ها، لیست قیمت و عنوان صفحات خودکار به‌روز می‌شوند.

پیاده‌سازی: `shared/lib/catalog.ts` (`isComingSoon`، `categoryRank`)؛ فیلتر قیمت در `price-board.ts` و `serializers.ts`.

## ۵. تابلوی قیمت و ساعت فروش

- هر محصول یک جدول قیمت دارد (مدل `PriceItem`: عنوان سایز، قیمت به تومان، وزن، توضیح، قیمت قبلی برای درصد تغییر).
- **ساعت فروش** (`shared/lib/market.ts`): پیش‌فرض شنبه تا چهارشنبه ۹ تا ۱۷، پنجشنبه ۹ تا ۱۳، جمعه تعطیل — به وقت تهران. از پنل ← «تابلوی قیمت» قابل تغییر؛ حالت دستی «باز» یا «بسته» هم دارد.
- **بیرون از ساعت فروش** سرور هیچ قیمتی نمی‌فرستد (حتی در HTML)؛ جای قیمت «استعلام» نوشته می‌شود.
- **به‌روزرسانی زنده**: صفحه‌ها هر ۵ ثانیه (فقط وقتی تب دیده می‌شود) نسخه تابلو را می‌پرسند؛ اگر تغییری بود کل داده را می‌گیرند و ردیف‌های تغییرکرده چند ثانیه رنگی می‌شوند.
- **تاریخ کنار هر ردیف** = تاریخ آخرین **تغییر** قیمت (نه آخرین تایید). متن صفحه می‌گوید قیمت نهایی، موجودی و هزینه حمل هنگام سفارش تایید می‌شود.
- **نمودار نوسان** هر ردیف (۷/۳۰/۹۰/۳۶۵ روز) از جدول `PriceHistory`.
- **ابزار ادمین**: ویرایش ردیف به ردیف، تغییر درصدی همه قیمت‌های یک محصول، ورود گروهی با پیست از اکسل، خروجی CSV در سایت.

## ۶. سئو

### متادیتا و عنوان‌ها

| صفحه | الگوی عنوان |
|---|---|
| خانه | خرید لوله کاروگیت با قیمت روز از کارخانه \| قدیر لوله آنلاین |
| لیست قیمت | لیست قیمت روز {دسته‌های فعال} {سال شمسی} |
| دسته فعال | قیمت {دسته} \| جدول سایز و خرید عمده |
| محصول | {نام محصول} \| مشخصات و قیمت (یا metaTitle دستی) |
| مقاله | metaTitle دستی یا عنوان مقاله |

همه صفحات `canonical` خودشان را دارند. نسخه `www` با ریدایرکت ۳۰۸ به دامنه اصلی منتقل می‌شود (`next.config.ts`).

### داده ساختاریافته (Schema)

| نوع | محل |
|---|---|
| Organization، HardwareStore/LocalBusiness (دفتر + کارخانه)، WebSite + SearchAction | خانه |
| BreadcrumbList | همه صفحات داخلی |
| CollectionPage + ItemList | صفحه دسته |
| Product + AggregateOffer | صفحه محصول — **فقط وقتی قیمت واقعی در صفحه هست** (دسته فعال و ساعت فروش)؛ قیمت به ریال |
| FAQPage | `/faq`، محصول و مقاله‌ای که سوال متداول دارد |
| BlogPosting | مقاله (تاریخ ویرایش واقعی؛ شمارش بازدید آن را عوض نمی‌کند) |

### سایت‌مپ و robots

- `/sitemap.xml` با هر درخواست از دیتابیس ساخته می‌شود؛ `lastmod` تاریخ واقعی تغییر است (برای محصول: آخرین تغییر محصول یا جدول قیمتش). صفحات ثابت بدون `lastmod`.
- `/robots.txt`: بستن `/admin/`، `/api/`، `/search?`.

### ابزارهای سئو در پنل («مرکز سئو»)

- **بررسی صفحات**: امتیاز سئو هر محصول، دسته، مقاله و پروژه و فهرست مشکلات (توضیحات متا، کلمه کلیدی، طول عنوان، محتوای کم، عنوان تکراری، …).
- **بهینه‌سازی خودکار** (بدون هوش مصنوعی، فقط فیلدهای خالی، با پیش‌نمایش): توضیحات متا، خلاصه، کلمه کلیدی، کوتاه‌کردن عنوان بلند، اسلاگ انگلیسی (با ریدایرکت خودکار). برای مقاله‌های فقط-PDF متن کلی و درست می‌سازد.
- **ریدایرکت‌ها**: با تغییر اسلاگ خودکار ثبت می‌شود؛ دستی هم قابل افزودن است.
- **تنظیمات**: کد تایید Google Search Console و متن سئوی پایین صفحه اصلی.

### نکات محتوایی پیاده‌شده

- پاسخ سوالات متداول همیشه در HTML (با CSS جمع می‌شوند، نه با حذف از DOM).
- هر مقاله به صفحه خرید دسته‌هایی که در متنش آمده و به لیست قیمت لینک می‌دهد.

## ۷. فرم‌ها، پیام‌ها و ردیابی تماس مشتری

### ثبت پیام

فرم مشاوره و فرم صفحه تماس ← `POST /api/contact` ← جدول `ContactMessage` همراه با **صفحه‌ای که فرم از آن ارسال شد** (`sourcePath`).

### ردیابی «کدام صفحه مشتری می‌آورد»

| اقدام | نحوه ثبت |
|---|---|
| کلیک روی هر لینک تلفن (`tel:`) | از مرورگر با `navigator.sendBeacon` به `/api/track` |
| کلیک روی لینک واتس‌اپ | همان |
| ارسال فرم مشاوره/تماس | سمت سرور هنگام ذخیره پیام |

- رویدادها در جدول `LeadEvent` (نوع، مسیر صفحه، شماره/موضوع، زمان).
- ربات‌ها، پیش‌نمایش لینک‌ها و درخواست نامعتبر ثبت نمی‌شوند؛ مسیر فقط مسیر داخلی سایت پذیرفته می‌شود.
- ردیاب (`features/leads/LeadTracker.tsx`) با event delegation روی کل صفحه کار می‌کند؛ لینک جدید تلفن یا واتس‌اپ بدون تغییر کد شمرده می‌شود.
- **گزارش**: پنل ← «گزارش تماس‌ها».

> کلیک لزوماً یعنی تماس موفق نیست، ولی برای مقایسه صفحه‌ها با هم معیار درستی است.

### اعلان پیام جدید

- زنگوله هدر: تعداد پیام‌های «در انتظار تماس» + فهرست با دکمه تماس.
- نشان قرمز کنار «پیام‌ها» در منو، شمارنده در عنوان تب مرورگر.
- پیام تازه ← اعلان روی صفحه (toast) و در صورت اجازه **اعلان مرورگر** (حتی وقتی تب در پس‌زمینه است).
- بررسی هر ۳۰ ثانیه و هنگام برگشتن به تب (`widgets/admin/AdminNotifications.tsx`).
- «پیگیری شد» فقط با دکمه صریح؛ باز کردن پیام وضعیت را عوض نمی‌کند.

> مقادیر تنظیمات عمومی (مثل `hero_title`) در دیتابیس بر مقادیر پیش‌فرض کد اولویت دارند.

## ۹. امنیت و دسترسی

- ورود با JWT در کوکی `admin_token` (اعتبار ۷ روز).
- صفحات `/admin` در `src/proxy.ts` فقط وجود و انقضای توکن را بررسی می‌کنند (نه امضا)؛ این کافی است چون همه داده‌های پنل از APIهایی می‌آید که امضای توکن را بررسی می‌کنند — ولی بهتر است proxy هم امضا را بررسی کند (نقشه راه).
- **همه APIهای نوشتنی و خصوصی** با `requireAdmin` (`shared/lib/admin-auth.ts`) محافظت می‌شوند؛ فرم تماس، ثبت کلیک و APIهای قیمت و جستجو عمومی‌اند.
- `?admin=true` در GETها (نمایش موارد منتشرنشده) فقط برای ادمین واردشده اثر دارد (`isAdmin`).
- مدیریت کاربران فقط با نقش `ADMIN`.
- آپلود تصویر و PDF فقط برای ادمین (توکن آپلود Vercel Blob هم فقط برای ادمین صادر می‌شود).
- تصاویر آپلودی با sharp دوباره کدگذاری می‌شوند (فایل غیرتصویری رد می‌شود).
- داده JSON-LD در برابر بیرون‌زدن از تگ `<script>` escape می‌شود.

موارد باز امنیتی در [نقشه راه](#۱۴-نقشه-راه) آمده است.

```bash
npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script
```

```bash
npm run dev          # اجرای محلی

npm run lint

```

| متغیر | کاربرد |
|---|---|

- ⚠️ `.env` محلی به دیتابیس اصلی وصل است؛ هر نوشتن در محیط محلی روی سایت واقعی اثر دارد.
- ⚠️ `npm run db:seed` رمز کاربر ادمین پیش‌فرض را به مقدار `README.md` برمی‌گرداند و داده نمونه اضافه می‌کند — **هرگز روی دیتابیس اصلی اجرا نشود**.
